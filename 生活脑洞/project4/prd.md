## 02. 唯一财务数据：月到手 8,000 元

**设定**：虚构年轻上班族，月度**税后到手工资 8,000 元**。剧情是“刚到账就迅速把钱分配完”的夸张表现；其中有当天已付的账单，也有对未来一个月预算的预留。主数字代表**还没安排的钱**，**不是银行实时余额**。

| 序号 | 项目 | 扣除额 | 分配后可安排金额 | 叙事与视觉身份 |
|---|---|---:|---:|---|
| 0 | 税后工资到账 | +¥8,000 | **¥8,000** | 昂首挺胸的小余额角色登场 |
| 1 | 房租 | -¥2,000 | **¥6,000** | 巨型房子像盖章机，一掌压走钱 |
| 2 | 吃饭 | -¥2,000 | **¥4,000** | 饭碗怪张嘴，吞走一大块钱 |
| 3 | 信用卡还款 | -¥1,100 | **¥2,900** | 卡片变磁铁，吸走钱条 |
| 4 | 交通通勤 | -¥400 | **¥2,500** | 小火车掠过，拖走一串硬币 |
| 5 | 水电网话 | -¥400 | **¥2,100** | 电表/账单图标弹出，咔嚓剪下一截 |
| 6 | 生活购物 | -¥900 | **¥1,200** | 购物袋大手抓住钱，顺势飞走 |
| 7 | 会员订阅 | -¥200 | **¥1,000** | 小小的“自动续费”回旋箭头最后偷走一口 |
| **合计** | **已付 + 已预留** | **-¥7,000** | **¥1,000** | **87.5% 已安排，12.5% 尚未安排** |

**必须执行的计算**：

```text
8000 - 2000 = 6000
6000 - 2000 = 4000
4000 - 1100 = 2900
2900 -  400 = 2500
2500 -  400 = 2100
2100 -  900 = 1200
1200 -  200 = 1000
合计支出 / 预留 = 7000
剩余可安排金额 = 1000
```

**业务准确性**：

1. “信用卡还款 ¥1,100”设定为**偿还上月已产生的消费**；“生活购物 ¥900”设定为**本月新预留预算**，两笔不是同一笔支出，不得重复计入。
2. 不要把“已安排 87.5%”说成“工资到账当天真实扣款 87.5%”。仅在剧情上表现账单抢钱，必要的脚注用“本片为虚构人物的月度预算演绎，非当天真实扣款记录”。
3. 屏幕主标签为“**还没安排的钱**”或“**可安排余额**”；不要写“实时存款”“银行卡余额”。
4. 剩下的 ¥1,000 **并不代表可长期随意消费或净储蓄**，结尾只说“就剩一千”，不声称每个人的收支如此。
5. 任何改变财务数据的创意都必须**先修改唯一数据源、重新核对全部节点**，不可临时在 UI 文案里改数。

## 03. 视觉导演方案：工资保卫战

### 核心叙事（一个视觉笑点贯穿全片）

工资到账时不是“手机 UI 弹出一张通知”就结束，而是 **¥8,000 化作一个会呼吸、会害怕的小小工资精灵**：蓝色圆角几何主体、亮黄钱袋小翅膀/圆形手脚、极简两点眼睛和嘴巴。七个支出项目不是表格，而是**七个具备独特抢钱动作的扁平怪物/道具角色**。每次被抢都直接影响主体尺寸与钱条长度，主体越来越瘦。最后主体变成一个“工资中转站”几何站牌，左侧新钱涌进，右侧七条出口通道迅速分流，自己只留一个小小的“¥1,000”。

**成熟感要求**：不是儿童教育片。角色五官极简，滑稽来自精确的反应时间、反差与动作节奏；画面构图干净、文字设计大胆、动效丝滑。不要设计一屏七个幼稚表情包。

### 色彩规范（严格控制到 5–6 个品牌色）

| 作用 | 色值 | 说明 |
|---|---|---|
| 主背景 / 大留白 | `#FFF6E9` | 温暖米白，必要时与蓝底进行形状擦除 |
| 主角与主数字辅助色 | `#2B2BFF` | 鲜明蓝，高饱和视觉支点 |
| 扣款/对抗强调 | `#FF5A4E` | 珊瑚红，不要满屏滥用 |
| 工资/金币强调 | `#FFC62B` | 明黄，到账正向情绪 |
| 次要信息/成功态点缀 | `#2EE6A8` | 薄荷绿 |
| 文字/深色底 | `#151433` | 深墨色，提高手机观看对比 |

- **纯色平面为主，不使用 3D 质感、玻璃拟态、大面积发光、真实纸张纹理或复杂渐变。**
- 抠形以 SVG / 几何 path / 2D Shape 为主；统一 2D 形状语法，允许少量纯色内部分割，不以描边堆满画面。
- 主数字始终是画面最高的文字视觉层级；字重和货币符号统一。
- 汉字采用有商业使用许可且支持全量简体中文的字体；数字建议重型无衬线；所有字体必须在渲染时可用，不得依赖某台机器上偶然安装的字体。

### 构图与安全区

- 画面尺寸 1080×1920，垂直构图；**主数字约 y=600–850 的视觉中心区**，角色动作围绕它展开。
- 左右关键文字边距至少 90px；上方建议留 160px、下方建议留 300px 做平台覆盖预留；结尾金句与数字不要被点赞/简介栏遮住。必要时按抖音、小红书、快手三端截图复核。
- 每一时刻只有一个主要抢钱动作；上一个角色撤场后下一个进场。不要同时涌入七个角色导致手机端看不清楚。
- 在扣款动作中可用**当前差额 `-¥X` + 结算后的大数字 `¥Y`** 双层信息；二者层级必须不同。
- 字幕可简练，不必把配音全文每一字都压在视觉中央。

## 04. 26 秒精确分镜（30 fps / 780 frames）

> 帧定义：时间范围为**左闭右开**。例如 0.0–2.0s = 第 0–59 帧。转场、金额结算、音乐重拍以统一 `cues.ts` 为准。以下安排为正式制作节奏，允许为真实配音在 ±0.15 秒内做微调，但不得改变总长、金额顺序和每笔结算结果；若调整，更新 cue sheet 和检查帧。

| 时间 | 帧范围 | 事件 / 画面 | 结算显示 | 动画与音效核心 |
|---|---:|---|---|---|
| **0.0–2.0s** | 0–59 | **开场钩子**：画面刚亮，巨大的 `¥8,000` 从顶部弹入，蓝色工资精灵抱着数字欢呼；“工资到账！”快速弹出 | **¥8,000** | 0.2s 内必须看见“工资/8000”，到账叮声、弹跳回弹，绝不黑场慢入 |
| **2.0–4.5s** | 60–134 | **房租第一击**：左侧巨型房子压来，印出 “房租 -¥2,000”，主角瞬间扁下去、钱条被抽走 | **¥6,000** | 第一个最重撞击，明确“压→夺走→数字变化” |
| **4.5–7.0s** | 135–209 | **吃饭第二击**：右侧饭碗张口咬住钱条，餐具一合，吞下 ¥2,000 | **¥4,000** | 弹性咬合、轻快咀嚼；主角回头瞪眼 |
| **7.0–9.5s** | 210–284 | **信用卡第三击**：带磁力的矢量卡片旋转进场，吸走 ¥1,100 | **¥2,900** | “磁吸+快速后撤”与音效同帧落点 |
| **9.5–11.5s** | 285–344 | **交通**：小火车横向掠过，拖走一排黄币 | **¥2,500** | 平移拉伸、车轮节奏，两拍快速完成 |

## 05. 音乐、撞击与镜头的共同时间轴

**目标**：音乐重拍真正“推着画面走”，不是随机到处甩转场。建议原创约 **120 BPM / 4⁄4** 的轻快 pluck / funk / 电子律动：每拍 0.5 秒，26s 共 52 拍，重拍天然落在整数秒或相邻重心。重点设计弹性打击音、金币哗啦、挤压、吸附、横向掠过；最后突然抽空再回归轻巧尾奏。

| 事件 | 关键音效 | 建议命中帧（可在局部微调） |
|---|---|---:|
| 工资到账 | 清脆「叮」+ 柔和上扬音阶 | 6（0.2s） |
| 房租砸下 | 低频 thump + 短弹簧回弹 | 105（3.5s） |
| 饭碗咬合 | pop / bite / gulp | 180（6s） |
| 信用卡吸走 | 吸力 whoosh + cash snap | 255（8.5s） |
| 通勤火车 | 横向 whoosh + tick | 315（10.5s） |
| 水电网话 | click + snip | 375（12.5s） |
| 购物大抓取 | 低频强击 + bag swoop | 450（15s） |
| 自动续费补刀 | 小声「啵」与 coin tick | 510（17s） |
| ¥1,000 静默 | 鼓组抽空，留短暂空气感 | 525–540（17.5–18s） |
| 中转站反转 | 矢量管道流动的节奏音、轻微反讽尾音 | 600–719（20–24s） |

- **先定音效 cue，再做动作**：同一个事件表要被画面和声音共同读取；可用 `cues.ts` 导出命中帧。
- 原创音乐与音效首选；现有参考视频的背景音乐**不要直接复用**，除非明确拥有合法使用权。若暂时无法获得合规配音/配乐，先输出**清楚标注“静音预览”**的动画版本并列出缺失资产，不得用无授权商用音乐假装最终交付。
- 人声始终明显高于 BGM；重要扣款的音效要有层次但不过度刺耳，检查削波和峰值。可参考目标响度约 -14 LUFS / 峰值不超过 -1 dBTP，若现有音频工具不支持可靠检测，就如实报告。

## 06. Remotion 实现要求

### 工程与组件

1. **先审视当前项目**的 `package.json`、Remotion 版本、已有 components、asset 目录和构建工具；优先增量开发，禁止覆盖或改坏其他已经做好的视频。
2. 本片**只创建一个正式 Composition**：`Salary8000FlatVector`。不要创建 `SalaryStyleA/B/C`、拼贴版、贴纸版等。
3. 示例建议结构（可按工程习惯调整）：

4. **动画可重复、确定性**：依据 `useCurrentFrame()`、`interpolate()`、`spring()` 或同等纯计算得到任何帧，不使用未经播种的随机数、依赖实时钟表的状态、`setTimeout` 驱动场景、渲染时异步图片请求。不使用仅在实时浏览器播放时可靠的 CSS transition 作为核心逻辑。
5. 角色以 SVG/HTML 2D 几何组合实现；适当使用父子锚点旋转与几何形变。基于 Remotion 原生时钟做动画，不是把参考项目网页视频嵌入到 Remotion 里。
6. 数字必须从**数据源派生**，不可为每次画面硬编码另一个剩余金额；每次扣款标签和主数字都由同一数据对象决定。
7. 在表现“抢钱”时保持金钱数值逻辑清晰：一笔扣款的动画播放期间，原总数→计数变化→结算正确值；数字不可在中间出现负数、`NaN`、额外千位或突然乱跳。
8. 转场必须是**几何元素带动**：例如房子下压带动整屏瞬间压缩、火车拉走横向色块、购物袋翻面变成下一幕背景、中转站由工资精灵本身形变。尽量避免全片统一淡入淡出、普通 PPT 卡片翻页。
9. 审美优先级：**一眼可读 > 动作因果 > 节奏冲击 > 细节装饰**。高密度动画应精确停住 6–10 帧让观众认出金额与项目。

### 数据源示例（可直接实现）

```ts
export const SALARY = 8_000;

export const EXPENSES = [
  { id: 'rent', label: '房租', amount: 2_000, settleFrame: 105 },
  { id: 'food', label: '吃饭', amount: 2_000, settleFrame: 180 },
  { id: 'credit', label: '信用卡还款', amount: 1_100, settleFrame: 255 },
  { id: 'transport', label: '交通通勤', amount: 400, settleFrame: 315 },
  { id: 'bills', label: '水电网话', amount: 400, settleFrame: 375 },
  { id: 'shopping', label: '生活购物', amount: 900, settleFrame: 450 },
  { id: 'subscriptions', label: '会员订阅', amount: 200, settleFrame: 510 },
] as const;

export const AMOUNTS_AFTER_EACH = EXPENSES.map((item, i) =>
  SALARY - EXPENSES.slice(0, i + 1).reduce((sum, it) => sum + it.amount, 0)
);

export const PLANNED_TOTAL = EXPENSES.reduce((sum, x) => sum + x.amount, 0);
export const FINAL_AVAILABLE = SALARY - PLANNED_TOTAL;

if (PLANNED_TOTAL !== 7_000 || FINAL_AVAILABLE !== 1_000) {
  throw new Error('工资分配数据有误');
}

export const CURRENCY = new Intl.NumberFormat('zh-CN', {
  style: 'currency', currency: 'CNY', maximumFractionDigits: 0,
});
```

**实现金额滚动提示**：如果有动画化数字 `interpolate`，开始值从本项之前的 `SALARY - 累计此前扣款` 计算，目标从 `AMOUNTS_AFTER_EACH[i]` 计算。数字显示应先经过 `Math.round` 后再做千分位格式化；结算帧显示精确的整数。

### 输出格式与技术验收

- 视频尺寸 **1080×1920**；帧率 **30**；时长 **26.000 秒**；总帧 **780**；H.264 MP4、有声版本应含 AAC 音轨。
- 建议先低分辨率预览关键镜头（1x/0.5x），完成后完整渲染；如必须分工，独立小组件可并行开发，但最终构图与金额校验必须整体复核。
- 制作时至少输出以下截图帧：`6, 45, 105, 180, 255, 315, 375, 450, 510, 555, 660, 750`；拼成 3×4 联系表，检查安全区、字体、层级与角色表达。
- 强制自动化检查：
  - `8000 - 7000 === 1000`
  - 逐项结果严格等于 `[6000, 4000, 2900, 2500, 2100, 1200, 1000]`
  - 事件结算帧严格递增并落在 `[0, 779]` 内
  - 每个结算时刻没有重复计数/错过结算
  - 片尾显示 `¥1,000`，字形无缺字，文本不会溢出竖屏安全区
  - 不出现与数字解释相矛盾的“余额”标签
  - 不出现黑帧、闪白帧、渲染崩溃和音画严重错位
- 使用 `ffprobe` 验证输出的实际时长、帧率、分辨率与音轨；本机可行时对音效峰值做检查。
- 若无授权配音或音乐，不要假装“已完成有声片”；可以先提交无声视觉版 + 缺失资源清单，但成片验收仍包含声音。
